# AuctionHouse.pk — 09 Nov, 2026

Prepared and tested locally. This work does not migrate or deploy the live website.

## Changes

1. **Pending review token entry:** administrators can enter and send Refundable Token Money for either project or custom properties using the separate form. The property amount can differ from the project's default; optimistic version checks remain in place.
2. **Customer navigation:** My Biddings and My Properties use light backgrounds and restrained borders, consistent with My Account. Their pages remain separate from the account sidebar.
3. **Home:** a smaller desktop flowchart, with “Click for LDA’s website”, “Click to Sell” and “Click to Buy”. Heading: “Where luck meets opportunity…”. Subtitle: “Compete in the open auction or negotiate on your terms.” Pine Axis Commercial and Pine Executive Residential appear on separate linked lines. The opportunity underline and existing typography remain.
4. **Projects Info:** a public navigation dropdown and server-rendered pages, initially `/projects-info/pine-axis` and `/projects-info/pine-executive`. Staff with Page Settings permission can add, edit, delete, order or hide information pages. Each has a tab name, title, content and up to five pictures. Images can appear above content, below content or after a chosen paragraph, with full-width, left or right alignment, captions and ordering controls. Text links use `[label](https://example.com)`; arbitrary HTML is escaped. Hidden pages leave the menu and sitemap. These information pages are separate from AH Projects' seller configuration.
5. **First-entry funding:** ordinary property cards, details, read-only Facts and Terms and repeat bid confirmations no longer show token amounts. Sellers see the requirement in the listing form (custom properties receive the amount after review); bidders see it at first participation entry. Accepting terms reserves the required money and fails if available funds are insufficient. Bid and negotiation actions retain their server checks. Existing accepted terms are backfilled as already disclosed. Money is reserved, not paid out.
6. **Negotiation:** all offers use a grid anchored to the starting price. For a Rs 200,000 start and Rs 1,000 interval, the highest offer is Rs 199,000. Both UI controls and server validation use this rule, including reopening. Legacy off-grid current offers no longer become a new grid anchor. The 40% floor, turn restrictions and own-offer improvement rules remain.
7. **Accounts:** no “Loading?” placeholder during tab changes; the previous view stays until data is ready. Balance entries use “Refund: Rs …” and “Received: Rs …”; the extra property token section is removed. The owner can view their decrypted, read-only CNIC in Account settings through a private authenticated endpoint. Public account responses do not expose it.
8. **Bidding and pending properties:** the current highest bidder cannot place another bid through the UI or API. Bid buttons return when another bidder takes the lead. Pending properties show red **PENDING** and **Listing pending for review**, with negotiation configuration unavailable until approval. The listing form says “Your property shall be reviewed after submission …”. Custom titles identify “Block A”, not just “A”.
9. **Negotiation controls:** the enable confirmation explains that bidders can negotiate below the starting price. “Enter negotiation with the Seller” sits immediately below the bid choices. Disabling negotiation blocks new direct entries and holding-period requests. Previously started private negotiations continue. Private negotiation messages and amounts stay limited to their parties.
10. **Accepted deals:** notifications identify the buyer's Bidding ID, property ID/title, accepted amount, accepting party, and date/time in PST, followed by the office visit instruction. Both parties are asked to refer to the property ID during their visit. New closed records retain the accepting party; historical negotiation records are backfilled from agreement events. The staff table includes IDs and 0.5% fees per party, expands into a full-width detail/checklist row, and downloads as Excel. Historical issued financial agreements remain unchanged.
11. **Formats:** all signed-in, fully activated staff can download named/described documents. Settings-permitted staff can upload, edit and remove them. PDF, DOCX and XLSX are supported up to 10 MB; files stay in private R2 storage and require staff access. Seller ownership documents remain PDF-only.
12. **Live data:** listing, customer-account, public-site and authenticated staff WebSocket channels push change signals through the existing Durable Object. The browser fetches authoritative data and patches the affected view without document reloads. Negotiation enable/disable, bids, public content edits, reviews, balances and administration updates propagate. Updates coalesce; reconnects reconcile data. Unsaved staff work is preserved behind an “Updates available” action. Private negotiation activity is not broadcast to public channels. Countdown ticks do not poll D1 every second. Scheduled opening/closing/holding boundaries reconcile the property once.

## Database and deployment

New migration: **`0008_orange_cargill.sql`**. It adds Projects Info and Formats tables, first-entry disclosure tracking, an explicit new-negotiation-disable flag and closed-deal accepting-party information, seeds the two project information pages, updates home copy and normalizes existing custom block titles. Migrations 0000–0007 are unchanged.

Source remains authoritative in `source/`. The compiled release is copied to `deployment/`. Preserve the existing **DB**, **BUCKET**, **LIVE_HUB** binding/migration, domain configuration and provider secrets. Never replace `PII_ENCRYPTION_KEY`: existing CNIC/address data depends on it.

## Transfer to the live website

1. Choose a quiet release window and finish or pause real operational work while backing up/migrating. Do not reset the database or bucket.
2. Open PowerShell in the prepared deployment folder:

   ```powershell
   Set-Location 'E:\Auction-House\AuctionHouse_Cloudflare\deployment'
   npm.cmd ci
   npm.cmd run login
   npm.cmd run whoami
   ```

3. Confirm Wrangler is using the existing Cloudflare account and inspect the configured DB, bucket and LIVE_HUB binding in `wrangler.json`. Keep the original PII encryption and Google/email secrets:

   ```powershell
   npx.cmd --no-install wrangler secret list --config wrangler.json
   ```

4. Export production D1 to a private local file. It includes customer data, so do not add it to the repository:

   ```powershell
   $auctionBackup = Join-Path $env:USERPROFILE ('Downloads\auctionhouse-before-nov9-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '.sql')
   npx.cmd --no-install wrangler d1 export DB --remote --config wrangler.json --output $auctionBackup
   ```

   Stop if the export fails or the account/database is wrong. Keep the previous Worker deployment version available for recovery.

5. Validate the package and inspect pending migrations:

   ```powershell
   npm.cmd run check
   npx.cmd --no-install wrangler d1 migrations list DB --remote --config wrangler.json
   ```

6. Apply pending migrations through **0008**, approving Wrangler's prompt after checking the database name:

   ```powershell
   npm.cmd run database
   ```

7. Deploy the prepared Worker and assets:

   ```powershell
   npm.cmd run deploy
   ```

8. After success, hard-refresh `https://auctionhouse.pk/` once to load the new asset bundle. This release reload is distinct from live bidding, which does not reload the page. Verify the two home project links and the Projects Info dropdown. In `/budapest-admin`, review the seeded project information and add the final project text/images and staff Formats.
9. Check the live site with separate seller and bidder sessions: editable review token, insufficient balance blocking first entry, hidden highest-bidder controls, private CNIC, pending status, and seller negotiation toggles appearing without bidder refresh. Check a synthetic closed deal's two notifications, IDs, office instructions, expandable checklist and Excel export. Verify real email delivery and Google sign-in separately.
10. Retain the backup and previous deployment version. If a production check fails, preserve the error and restore the prior Worker version as appropriate; do not run destructive reverse SQL or rotate the encryption key. The added schema is compatible with the previous application, although data edits should be reviewed before any recovery.

For a later source edit, rebuild and repackage before repeating the deployment steps:

```powershell
Set-Location 'E:\Auction-House\AuctionHouse_Cloudflare\source'
npm.cmd ci
npm.cmd run typecheck
npm.cmd run build
npm.cmd run deploy:package
```
